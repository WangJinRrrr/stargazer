# Stargazer 待办（Todo）设计

日期：2026-09-23
状态：待用户评审
上位文档：`docs/superpowers/specs/2026-09-22-stargazer-design.md`（本文件细化其 §11.3，并在冲突时取代之）

## 1. 目标与定位

**一句话**：一个“随手一记”的地方 —— 按一下热键、`Ctrl+V` 粘进任何东西、`Esc` 走人。

要收三种内容，且**用户不需要先选类型**：

1. 文字（自己输入或粘贴多行文本）
2. 网页链接（粘贴后能直接点开进默认浏览器）
3. 图片（粘贴的截图或图片文件，列表里能预览）

保持简洁的核心手法：

- **只增加一个概念**：条目类型由粘贴的内容自动判定，不提供“新建文字 / 新建链接 / 新建图片”的选择器。
- **只有一种条目结构**：文字、链接、图片的差别只在渲染与点击行为，存储上是同一行的不同字段。
- **只有一个输入通道**：底部常驻输入框，`Ctrl+V` / 拖入 / 打字都走它。
- **复用已有零件**：剪贴板模块、线程 B、图标那套“工作线程解码 → 缓存 → UI 建位图”的范式、`InlineEdit`、行格式转义、收纳盒的失效灰显。

### 明确不做（YAGNI）

截止日期、优先级、提醒/通知、子任务、标签、分组、富文本、图片编辑（裁剪/标注）、拖动排序、多选、搜索过滤、云同步、过期自动清理、完成态的归档文件。

（原 spec §11.3 写的 `due` / `prio` 字段随之**删除**：`todo.txt` 从未被创建过，改格式零迁移代价。）

## 2. 数据模型

`data/todo.txt`，一行一条，Tab 分隔，字段内转义沿用全局规则（`||` `|t` `|n`）：

```
id \t done \t created \t kind \t text \t attach
```

| 字段 | 含义 |
|---|---|
| `id` | 单调递增整数，用作稳定排序键与图片文件名 |
| `done` | `0` / `1` |
| `created` | Unix 秒 |
| `kind` | `text` / `link` / `image` |
| `text` | 文字内容；`link` 时是 URL；`image` 时可空（显示图名） |
| `attach` | `image` 时的图片来源路径，其余为空 |

规则：

- **空行不产生幽灵条目**：`kind`、`text`、`attach` 同时为空的行按坏行跳过并计数（与 `boxes.txt` 同一套约定）。
- `kind` 是白名单以外的值（手改数据造成，比如 `foo`）→ **按 `text` 处理**，不丢内容也不报错（宽松原则：宁可当普通文字，也不要让用户的记录凭空消失）。
- `created` 为 0 或负数（手改）→ 视为 0（永远排在末尾），排序不依赖它的合理性。
- 坏行跳过、计数，加载后托盘气泡提示一次（沿用现有机制）。
- 整体解析失败（编码不对）→ 备份 `.bad` 并重建（沿用现有机制）。

### 图片的两种来源，统一到 `attach` 一个字段

| 来源 | `attach` | 说明 |
|---|---|---|
| 剪贴板位图（截图，`CF_DIB`） | `data\images\<id>.png` | 由本程序编码落盘的**副本**，随程序一起便携 |
| 粘贴/拖入的图片文件（`CF_HDROP`） | 该文件的绝对路径 | **引用**，不复制内容，不占空间 |

### 副本的所有权与清理（唯一会删磁盘的地方在此）

- 副本仅指 `attach` 位于 `<exe>\data\images\` 下的文件。
- 删条目（含“清空已完成”）时，若该副本**不再被任何其他条目**的 `attach` 指向（大小写不敏感比较），则删除该文件。
- **绝不删除** `data\images\` 以外的任何路径 —— 引用型图片被删只删条目。
- 手改数据或手动清空 `data\images\` 不会导致崩溃：图片条目退化为“图片已不存在”（见 §5）。

## 3. 输入流水线（唯一的判定优先级）

输入通道：底部常驻 `EDIT`（打字 / `Ctrl+V` / 右键粘贴）、面板拖入（`IDropTarget` 已存在）。

判定顺序（**用户不需要做任何选择**）：

1. 剪贴板有 `CF_HDROP` → **逐个路径**看：是图片的就各记一条（`kind=image`，`attach=该路径`）；如果全部都不是图片，则改用**托盘气泡提示**“待办只收文字、链接和图片”，不产生条目（多选拖入多张图 = 多条）。
2. 剪贴板是文本，去掉首尾空白后非空 → 以 `http://`/`https://` 开头（大小写不敏感）就是 **link**，否则 **text**。
   **文本优先于位图**：Excel 复制单元格、Word 复制图文时剪贴板里同时有文本与位图，
   若位图优先，一个单元格会变成一张图。
3. 剪贴板有位图（`CF_DIBV5` / `CF_DIB`）→ 在工作线程用 WIC 编码成 PNG → `data\images\<id>.png` → **图片（副本）**。
4. 什么都没有 → 不动（`Ctrl+V` 粘空剪贴板是常见误操作，不值得提示）。

细节：

- **文本 Ctrl+V 落在输入框里**（可改错字、可多行），**回车才入列**；图片/文件粘贴**直接入列**
  （它们没法在输入框里编辑）。两类都只多一次回车。
- `EDIT` 子控件自己会处理文本粘贴，所以图片/文件的判定必须在它之前：复用 `InlineEdit::on_key` 钩子，
  在 `Ctrl+V` 上先看剪贴板，有文件或位图就自己接管；纯文本则返回 `false`，让 EDIT 自己粘。
- 图片扩展名白名单（大小写不敏感）：`png jpg jpeg gif bmp webp ico tif tiff`。
- 位图（截图）落盘时 `text` 留空（行内显示文件名，见 §5）。
- 位图编码失败时**回滚刚插入的条目** + 托盘气泡（宁可没记上，也不留一条永远提示“图片已不存在”的残条）。
- 判定函数是**纯函数**（`model/todo_kind`），因此可被 `test_model` 覆盖。
- 拖入非图片文件同样走第 1 条（气泡提示，不建条目）。

## 4. 排序与显示顺序

`sort_todos()`（已存在，需按新模型改写）：

1. 未完成在前，已完成沉底；
2. 同组内按 `created` 降序（**新条目置顶**）；
3. `created` 相同则按 `id` 降序（保证稳定，同一秒内连记多条不会乱跳）。

## 5. 视图：布局、渲染、交互

顶部沿用视图标签行（`收纳盒 / 待办 / 浏览`），底部是常驻输入框，中间是单列列表。

### 布局

- 输入框：窗口底部，高 34 逻辑像素（`kTodoInputH`）。
- 列表区：标签行之下到输入框之上，四周 `kPad`。
- **行高两种**，按 `kind` 决定：文字/链接 28，图片 96（缩略图 + 图名）。
  列表变化时算一次**行偏移前缀和**，滚动与命中都用二分查找 —— 虚拟化仍然精确，不依赖“等行高”。
- 只渲染可见行（含跨越上下边界的那一行）。

### 每行画什么

| kind | 左侧 | 中间 | 右侧/样式 |
|---|---|---|---|
| text | 自绘复选框 | 文字（多行截断为 2 行） | — |
| link | 自绘复选框 | URL 文本，**下划线 + 主题强调色** | 点击/回车进默认浏览器 |
| image | 自绘复选框 | 缩略图（等比缩放进 160×88 逻辑框，居中） | **右侧**两行小字：第 1 行显 `text`（空则文件名），失效时第 2 行显“图片已不存在” |

- 已完成条目：整行灰显（`theme.text_dim`）+ 复选框打勾；仍可点击、可删除。
- 图片缺失（`attach` 指向的文件不存在）→ 该行灰显 + 删除线 + 文案“图片已不存在”（复用收纳盒的失效视觉语言）。

### 缩略图（预览）

- 用 **`IShellItemImageFactory::GetImage`** 拿系统缩略图（一行调用，且 Windows 自带缩略图缓存），请求 192×192 物理像素；
  只给 `SIIGBF_THUMBNAILONLY` 失败时退一步只给 `SIIGBF_BIGGERSIZEOK`。
- 在**自己的缩略图线程**（第三条工作线程，STA）取，得到 BGRA 像素后交给 UI 线程 `make_bitmap`
  （照搬 `icons.cpp` 的范式：**`WM_PAINT` 里绝不调 Shell**，取不到就画占位，完成后 `PostMessage(WM_APP_IMAGE_READY)` 标脏重绘）。
- UI 侧 LRU 缓存位图，上限 32 张（约 4.7 MB）；设备丢失时丢弃位图、保留像素。
  - `ponytail:` 缓存的键是规范化路径、不带 mtime：图片内容极少变，改图后重启即刷新。
- **取图失败会记入负缓存**，避免每次重绘都重新去问 Shell（断网盘上每次请求可能要等超时）；
  呼出时清空负缓存，所以“把文件改回来再呼出”能恢复预览。
- 取缩略图失败（格式怪、网盘断、权限）→ 画扩展名色块占位（复用 `ext_color`），**不弹任何框**。
- 引用型图片的存在性校验复用 `fs_work` 的 `fs_check_paths`：呼出时投递当前列表里的 `attach` 路径，结果按 path 回填。
  注意：`fs_work` 的回调是单槽设计，且收纳盒也在用它 —— 因此**回调在 app 层统一设置一次**，一次回填 `boxes` 与 `todos` 两边的同路径条目（不新增第二份消费者，保持 `fs_work` 现状）。

### 键盘与鼠标

| 输入 | 行为 |
|---|---|
| `↑` `↓` `PgUp` `PgDn` `Home` `End` | 移动选中行（保持可见） |
| `Space` 或单击复选框 | 切换完成态 |
| `Enter` / 双击 | 打开：链接→默认浏览器；图片→系统看图；文字→无动作 |
| `Del` | 删除条目（图片副本按 §2 规则清理） |
| `F2` | 改文字（仅 `text` / `link`；图片条目无文字可改） |
| `Ctrl+C` | 复制：文字/链接 → 纯文本；图片 → `CF_HDROP`（复用剪贴板模块） |
| `Ctrl+V` | 走 §3 输入流水线 |
| 输入框回车 | 提交一条（文字或链接，按 §3 判定），清空输入框并保持焦点 |
| 滚轮 | 滚动列表 |

打开链接或图片后**隐藏面板**（与收纳盒/浏览一致：别让 TOPMOST 挡住刚打开的东西）。

### 右键菜单

打开 / 复制 / 编辑 / 删除 / 清空已完成 / 在资源管理器中显示（仅图片）/ 粘贴（走输入流水线）。

## 7. 线程与错误处理

- 剪贴板读取在 UI 线程（快，本地）。图片编码与文件写入在工作线程（4K 截图编码可达上百毫秒，不能卡 UI）。
- 缩略图获取在工作线程；`WM_PAINT` 绝不触发 Shell 调用。
- 失败一律降级 + 托盘气泡，不弹模态框：图片存不下（磁盘满/只读）→ 条目不入库并提示；缩略图取不到 → 占位块；链接打不开 → 气泡提示。
- 数据落盘沿用现有规则：变更即写、原子替换、写失败托盘警告一次。

## 9. 验收标准

1. 呼出 → `Ctrl+V` 粘一段文字 → 回车，列表顶部出现该条目；重开程序仍在。
2. 粘 `https://…` → 该行是链接样式，`Enter` 或双击进默认浏览器。
3. 粘截图（Win+Shift+S）→ 列表出现缩略图；`data\images\<id>.png` 存在；搬到别的目录后仍能预览（便携）。
4. 粘/拖一个磁盘上的图片文件 → 只记引用；把那个文件改名 → 该行灰显 + 删除线 + “图片已不存在”。
5. `Space` 勾掉 → 该行沉底灰显；「清空已完成」后它消失，且只删掉属于它的 `data\images` 副本，其他条目的图片完好。
6. `Del` 删一条文字条目 → 磁盘上没有任何文件被删（除 §2 允许的副本）。
7. 图片很多（例如 200 条含图）时滚动流畅、内存不爆（缩略图 LRU 上限 32 张）。
8. 空闲时无定时器、无轮询（与全局一致）。
